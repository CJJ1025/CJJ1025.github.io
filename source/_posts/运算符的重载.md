运算符重载让自定义类型也能使用 `+`、`<<`、`[]` 这些符号，写出的代码更自然。本文从本质讲起，覆盖成员/友元两种实现方式、前后置 `++`、以及只能作为成员函数重载的几个运算符。

## 一、本质：运算符重载就是函数重载

给运算符写一个函数，「运算符符号」就是函数名：

```cpp
返回类型 operator运算符(参数列表)
```

例如重载 `<<`，它的函数名就是 `operator<<`。调用时有两种写法，完全等价：

```cpp
cout << a;              // 运算符写法（推荐，更自然）
operator<<(cout, a);    // 函数调用写法
```

所以 `cout << a << b` 实际是嵌套调用：

```cpp
operator<<(operator<<(cout, a), b);
```

**规则**（这几条必须记住）：

- 不能改变**操作数个数**：双目运算符重载后仍是双目；
- 不能改变**优先级和结合性**；
- 不能发明新的运算符；
- 至少有一个操作数是**类类型或枚举类型**（不允许重载 `int + int`）；
- 最好**遵循内置运算符的语义**——让 `+` 表现得像加法，而不是让人猜。

## 二、第一个例子：重载 `<<` 输出 vector

```cpp
#include <iostream>
#include <vector>
using namespace std;

// 全局重载 <<，支持直接输出 vector<int>
ostream& operator<<(ostream& os, const vector<int>& v) {
	os << "[";
	for (int i = 0; i < (int)v.size(); i++) {
		if (i > 0) os << ",";
		os << v[i];
	}
	os << "]";
	return os;      // 返回 os，支持链式 cout << a << b;
}

int main() {
	vector<int> number{1, 2, 3, 4, 5, 6, 7, 8, 9};
	cout << number << endl;     // [1,2,3,4,5,6,7,8,9]
	return 0;
}
```

**为什么返回值类型和第一个参数类型相同（`ostream&`）？** 因为 `cout << a << b` 是左结合的，即 `(cout << a) << b`。只有让 `cout << a` 的结果仍然是 `ostream`，后面才能继续 `<< b`。这就是所谓的「支持链式调用」。

## 三、作为成员函数重载

拿复数类举例，`+` 和 `*` 都作为成员函数重载：

```cpp
#include <iostream>
using namespace std;

class Complex {
private:
	double r;      // 实部
	double i;      // 虚部
public:
	Complex(double real = 0, double imag = 0) : r(real), i(imag) {}

	Complex operator+(const Complex& other) const {
		return Complex(r + other.r, i + other.i);
	}

	Complex operator*(const Complex& other) const {
		// (a+bi)(c+di) = (ac-bd) + (ad+bc)i
		return Complex(r * other.r - i * other.i,
		               r * other.i + i * other.r);
	}

	void print() const {
		cout << r << " + " << i << "i" << endl;
	}
};

int main() {
	Complex a(1, 2), b(2, 1);
	Complex c = a + b;      // 等价 a.operator+(b)
	Complex d = a * b;
	a.print();      // 1 + 2i
	b.print();      // 2 + 1i
	c.print();      // 3 + 3i
	d.print();      // 0 + 5i
	return 0;
}
```

> 复数乘法不是「实部乘实部、虚部乘虚部」，而要按 `(a+bi)(c+di) = (ac-bd) + (ad+bc)i` 展开。

**成员函数形式的特点**：左操作数就是调用它的对象（隐含 `this`），所以**左操作数必须是本类对象**。这带来一个限制——`c1 + 2.0` 可以（`2.0` 隐式转换成 `Complex`），但 `2.0 + c1` **不行**，因为 `double` 没有成员函数 `operator+`。下一节解决这个问题。

## 四、友元函数重载

把运算符写成**全局函数**，两边都能自动转换：

```cpp
#include <iostream>
using namespace std;

class Complex {
private:
	double imag;
public:
	Complex(double i = 0) : imag(i) {}

	friend Complex operator+(const Complex& c1, const Complex& c2);
	friend Complex operator+(double num, const Complex& c);
	friend Complex operator+(const Complex& c, double num);
};

Complex operator+(const Complex& c1, const Complex& c2) {
	return Complex(c1.imag + c2.imag);
}
Complex operator+(double num, const Complex& c) {
	return Complex(num + c.imag);
}
Complex operator+(const Complex& c, double num) {
	return Complex(c.imag + num);
}

int main() {
	Complex c1(3), c2(5);
	Complex c3 = c1 + c2;
	Complex c4 = c1 + 2.0;      // 成员版本也能做到
	Complex c5 = 2.0 + c1;      // 只有友元全局版本能做到！
	return 0;
}
```

**为什么友元版本两边都支持？** 内置运算符的两侧是平等参与重载决议的，`2.0` 可以被隐式转换成 `Complex`，于是 `operator+(double, const Complex&)` 匹配成功。而成员函数版本的左操作数位置永远是 `this`，`double` 占不了这个位置。

注意：**友元函数虽然写在类里，但它不是成员函数**，而是类外部的函数——所以它没有 `this`，也没有 `const` 修饰。

> 关于友元的三种形式和注意事项，见 [C++ 友元（friend）详解](/2026/09/26/函数的一些知识/)。

## 五、前置 `++` 与后置 `++`

C++ 用**参数列表**来区分两者：后置版本多一个 `int` 参数，这个参数**只是占位符**，调用时不需要也不能传实参。

| 对比项 | 前置 `++obj` | 后置 `obj++` |
| --- | --- | --- |
| 函数签名 | `Demo& operator++();` | `Demo operator++(int);` |
| 返回什么 | 修改后的**原对象本身** | 修改前的**对象副本** |
| 返回类型 | 引用 `Demo&` | 值 `Demo` |
| 拷贝开销 | 无，高效 | 需要拷贝对象，开销大 |
| 能否嵌套 | `++(++obj)` 合法 | `(obj++)++` 不支持 |

```cpp
#include <iostream>
using namespace std;

class Demo {
private:
	int m_a;
public:
	Demo(int a = 0) : m_a(a) {}

	// 前置：++obj
	Demo& operator++() {
		++m_a;
		return *this;      // 返回自身引用，才能 ++(++obj)
	}

	// 后置：obj++（int 只是占位符，用于和前置版本区分）
	Demo operator++(int) {
		Demo tmp = *this;  // 1. 保存修改前的状态
		++m_a;             // 2. 复用前置版本完成自增
		return tmp;        // 3. 返回旧值的副本
	}

	int get() const { return m_a; }
};

int main() {
	Demo d(5);
	cout << (++d).get() << endl;   // 6：先自增，再取值
	cout << (d++).get() << endl;   // 6：返回的是自增前的旧值
	cout << d.get() << endl;       // 7：对象本身确实已经变成 7
	return 0;
}
```

**这一组差异解释了为什么后置 `++` 效率更低**：它必须额外拷贝一份对象来保存旧状态。所以对自定义类型，能用前置就用前置（`for (auto it = v.begin(); it != v.end(); ++it)` 里写 `++it` 而不是 `it++`，是老手习惯）。

## 六、只能作为成员函数重载的运算符

有四个运算符**必须**写成成员函数：

| 运算符 | 说明 |
| --- | --- |
| `=` | 赋值 |
| `[]` | 下标 |
| `()` | 函数调用 |
| `->` | 成员访问（箭头） |

其中**赋值运算符 `=` 编译器会自动生成一个默认版本**，它做的是**逐成员的浅拷贝**。如果类里管理了指针等资源，默认版本会导致两个对象指向同一块内存，析构时重复释放（double free）——这时你必须自己重载 `=`，并同时提供拷贝构造函数和析构函数，这就是常说的「三法则（Rule of Three）」。

## 七、函数调用运算符 `()`

重载 `()` 后，对象可以像函数一样被调用，这种对象叫**仿函数（functor）**：

```cpp
返回类型 operator()(参数列表)
```

```cpp
#include <iostream>
using namespace std;

struct LinearFunction {      // 一次函数 f(x) = kx + b
	double k;
	double b;
	double operator()(double x) const {
		return k * x + b;
	}
};

int main() {
	LinearFunction f{1.5, 3};
	cout << "f(0)=" << f(0) << endl;      // 3
	cout << "f(3)=" << f(3) << endl;      // 7.5
	return 0;
}
```

仿函数在标准库中大量使用——它们可以作为算法的「谓词」传入，还比函数指针更容易保存状态（状态就存在对象成员里）。

## 八、解引用 `*` 与箭头 `->`

这两个运算符用来模拟指针行为，是智能指针的实现基础：

```cpp
#include <iostream>
using namespace std;

class MyPtr {
	int* p;
public:
	MyPtr(int* ptr) : p(ptr) {}
	// 解引用：返回引用，才能 *obj = 200 这样写
	int& operator*() {
		return *p;
	}
	~MyPtr() { delete p; }
};

int main() {
	MyPtr obj(new int(100));
	cout << *obj;        // 等价 obj.operator*()
	*obj = 200;          // 返回引用，所以可以赋值
	cout << *obj;        // 200
	return 0;
}
```

> ⚠️ 这个 `MyPtr` 有隐患：它析构时 `delete p`，但没有自己写拷贝构造函数和拷贝赋值。一旦发生拷贝，两个对象会同持一块内存，析构时 **double free**。这正是上面提到的三法则问题，真实代码里必须补齐。

`operator->` 有个特殊规则：它返回一个指针，编译器会**自动对返回值再应用一次 `->`**。所以 `p->val` 实际是 `(p.operator->())->val`：

```cpp
#include <iostream>
using namespace std;

struct Data {
	int val = 10;
};

class MySmartPtr {
	Data* ptr;
public:
	MySmartPtr(Data* p) : ptr(p) {}
	Data& operator*() { return *ptr; }
	Data* operator->() { return ptr; }   // 返回指针，编译器会自动再取一次 ->
};

int main() {
	MySmartPtr p(new Data);
	cout << (*p).val;      // 解引用后用 .
	cout << p->val;        // 箭头，调用 operator-> 后再自动 ->
	return 0;
}
```

## 九、下标运算符 `[]`

下标运算符通常要写**两个版本**：一个返回非 const 引用（可读可写），一个 const 版本返回 const 引用（只读）：

```cpp
#include <iostream>
using namespace std;

class Arr {
	int data[5] = {1, 2, 3, 4, 5};
public:
	int& operator[](int idx) {              // 读写版本
		return data[idx];
	}
	const int& operator[](int idx) const {  // 只读版本（const 成员函数）
		return data[idx];
	}
};

int main() {
	Arr a;
	a[1] = 99;              // 调用非 const 版本，返回引用才能赋值
	cout << a[1] << endl;   // 99

	const Arr b;            // const 对象
	cout << b[2];           // 只能调用 const 版本
	return 0;
}
```

**为什么必须写两个？** const 对象不能调用非 const 成员函数。如果只有非 const 版本，`const Arr b; b[2]` 就会编译失败。注意 `[]` 本身**不做越界检查**，需要的话得自己加，或改用 `at()`。

## 十、类型转换运算符

让自定义类型能转换到别的类型，写法是 `operator 目标类型()`：

```cpp
#include <iostream>
using namespace std;

class Complex {
private:
	double r, i;
public:
	Complex(double real, double imag) : r(real), i(imag) {}

	operator double() const {      // 转换成 double 时，返回实部
		return r;
	}
};

int main() {
	Complex a(0.1, 2);
	cout << double(a);      // 0.1，显式转换
	return 0;
}
```

有了它，`Complex` 就能被用在需要 `double` 的地方（包括隐式转换）。**但要小心**：隐式转换运算符会带来意外的类型转换和重载歧义。如果只想支持显式转换，加上 `explicit`：

```cpp
explicit operator double() const { return r; }   // 只能 double(a)，不能隐式转换
```

同理，`explicit operator bool()` 是判断对象有效性的常见写法（且它能安全地用于 `if (obj)`，不会像 `operator int` 那样被意外参与算术运算）。

## 十一、不能重载的运算符

以下运算符**不允许重载**：

| 运算符 | 说明 |
| --- | --- |
| `.` | 成员访问 |
| `::` | 作用域解析 |
| `.*` | 成员指针访问 |
| `->*` | 成员指针箭头 |
| `?:` | 三目条件运算符 |
| `sizeof` | 求大小 |
| `typeid` | 类型信息 |
| `alignof` | 对齐要求（C++11） |

另外 `#` 和 `##` 是**预处理指令**，不属于运算符，自然也谈不上重载。

还有一条容易忽略的限制：`&&` 和 `||` **可以**重载，但重载后会**失去短路求值特性**（因为变成了普通函数调用，两边参数都要先求值）。所以实践中几乎没有人重载它们。

## 十二、小结

- 运算符重载本质是**函数重载**，函数名形如 `operator+`；`cout << a` 等价于 `operator<<(cout, a)`；
- 不能改变操作数个数、优先级、结合性，也不能发明新运算符；至少一个操作数须为类/枚举类型；
- **成员版本**的左操作数必须是本类对象；**友元全局版本**两侧都能隐式转换，`2.0 + c1` 这种情况必须用友元；
- 前置 `++` 返回**引用**、无拷贝；后置 `++` 靠占位 `int` 区分、返回**值**、有拷贝开销；
- `=` `[]` `()` `->` **只能作为成员函数**重载；默认的 `=` 是浅拷贝，管理资源时要自己写（三法则）；
- 下标运算符要写**非 const + const 两个版本**，否则 const 对象无法使用；
- 类型转换运算符尽量加 `explicit`，避免隐式转换带来的意外；
- `.` `::` `.*` `->*` `?:` `sizeof` `typeid` `alignof` **不能重载**；`&&`/`||` 可以但会失去短路特性。
